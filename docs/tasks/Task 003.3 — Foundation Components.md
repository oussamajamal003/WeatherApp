# Task 003.3 — Foundation Components

## Feature

Implement the reusable foundation UI components defined in the approved WeatherApp Design System.

---

## Branch

feature/foundation-components

---

## Target

develop

---

# Objective

Implement the reusable foundation component library exactly as defined in the approved Design System.

These components will become the building blocks for every future page and feature.

The implementation must be production-ready, reusable, accessible, theme-aware, responsive, and fully aligned with the approved design.

No weather-specific functionality or application pages should be implemented during this task.

---

# Dependencies

This task depends on:

- ✅ Task 003.1 — Theme Foundation & Design Tokens
- ✅ Task 003.2 — Layout System Foundation

Reuse the existing Theme Provider, Design Tokens, Layout System, and shared utilities.

Do not duplicate existing code.

---

# Design Source of Truth

The approved `Design/` directory is the ONLY source of truth for all visual implementation.

Before writing any code, review:

- Design/README.md
- Design/FIGMA_IMPLEMENTATION_RULES.md
- Design/Components/
- Design/Specs/
- Design/Tokens/
- Design/Variables/
- Design/Playground/

Read the README.md inside every relevant folder.

Review every screenshot related to the components before implementation.

Treat every screenshot as an implementation specification.

Never implement from the React code generated by Figma Make.

Never redesign.

If any design is ambiguous:

- Stop.
- Document the ambiguity.
- Identify the affected screenshot(s).
- Explain exactly what information is missing.
- Request clarification.
- Do not invent UI.

# Requirements

Every component must exactly match the approved Design System.

Never approximate:

- Colors
- Typography
- Padding
- Margins
- Border radius
- Shadows
- Elevation
- Borders
- Icons
- Component states
- Variants

Always:

- Use Design Tokens.
- Use Theme variables.
- Support Light Theme.
- Support Dark Theme.
- Be reusable.
- Be composable.
- Be fully typed.
- Follow project coding standards.
- Avoid duplicated code.

---

# Accessibility Requirements

Every component must:

- Support keyboard navigation.
- Preserve visible focus.
- Meet accessibility requirements.
- Support screen readers where applicable.
- Use semantic HTML.
- Respect disabled states.
- Respect loading states.
