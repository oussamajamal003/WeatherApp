# Task 003.1 — Theme Foundation & Design Tokens

## Feature

Implement the approved WeatherApp Design System foundation in React.

---

## Branch

feature/theme-foundation

---

## Target

develop

---

# Objective

Implement the visual foundation of the WeatherApp exactly as defined in the approved Design System.

This task establishes the application's reusable design infrastructure that all future UI components and pages will depend on.

No application pages or weather functionality should be implemented during this task.

---

# Design Source of Truth

The approved Design/ directory is the ONLY source of truth for all visual implementation.

Before writing any code, review:

- Design/README.md
- Design/FIGMA_IMPLEMENTATION_RULES.md
- Design/Cover/
- Design/Tokens/
- Design/Variables/
- Design/Components/
- Design/Specs/
- Design/Layouts/
- Design/Playground/

Read the README.md inside every relevant folder.

Review every screenshot related to this task.

Treat every screenshot as an implementation specification.

Never implement from the React code generated by Figma Make.

Never redesign.

If any design is ambiguous:

- Stop.
- Document the ambiguity.
- Identify the affected screenshot(s).
- Explain exactly what information is missing.
- Request clarification.
- Do not invent UI.

---

# Scope

Implement ONLY the design foundation.

Required implementation:

- Theme Provider
- Theme Context
- Theme Toggle
- Light Theme
- Dark Theme
- CSS Variables
- Tailwind Theme Extension
- Semantic Design Tokens
- Color System
- Typography System
- Spacing Scale
- Radius Scale
- Shadow System
- Elevation Tokens
- Global Theme Styles
- Base Application Styles

---

# Out of Scope

Do NOT implement:

- Application pages
- Layouts
- Navigation
- Weather components
- Search UI
- Forecast UI
- API integration
- Business logic
- State management unrelated to theming
- Mock data

---

# Requirements

Every implementation must exactly match the approved Design System.

Never approximate:

- Colors
- Typography
- Spacing
- Radius
- Shadows
- Elevation
- Responsive behavior

Always:

- Use semantic design tokens.
- Use CSS variables.
- Extend Tailwind using design tokens.
- Avoid hardcoded values.
- Keep the implementation reusable.
- Keep styling centralized.
- Follow project coding standards.
- Follow the existing architecture.

---

# Acceptance Criteria

The task is complete only when:

- Theme Provider is implemented.
- Theme Context is implemented.
- Light Theme is implemented.
- Dark Theme is implemented.
- Theme switching works correctly.
- Design tokens are implemented.
- CSS variables are used consistently.
- Tailwind theme is configured.
- No hardcoded design values remain where tokens should be used.
- Implementation matches the approved Design screenshots.
- No visual redesign has occurred.
